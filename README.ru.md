# SC Hub

[English](README.md) | **Русский**

Консольный набор инструментов в одном файле для **ресурсов Supercell `.sc`** (SC1 и SC2): конвертация PNG/GIF в `.sc`,
разбор и правка готовых файлов, перестройка атласов, объединение и очистка, анимированные фоны меню и свои загрузочные экраны.
Рассчитан на клиентские моды (например, в стиле Brawl Stars / Null's Brawl).

- Один файл: `sc_hub.py`. Нужен только Python и несколько pip-пакетов (ставятся сами).
- Управление меню: выбери номер, ответь на вопросы, **Enter подставляет значение в `[скобках]`**.
- Интерфейс на **русском и английском** (переключение `L` в меню, `--lang en|ru`, переменная `SCHUB_LANG`).
- Windows / Linux / macOS.

> **Отказ от ответственности.** SC Hub — неофициальный инструмент сообщества, он не связан с Supercell и не одобрен ею.
> В нём нет ресурсов игры. За обрабатываемые файлы и соблюдение правил игры отвечаешь ты. Результаты проверялись разбором
> и рендером получившихся файлов; в самой игре поведение может отличаться — храни копии оригиналов.

## Быстрый старт

1. Установи **Python 3.9+** (в Windows отметь «Add Python to PATH»).
2. Скачай репозиторий (или только `sc_hub.py`).
3. Запусти:
   - Windows: двойной щелчок по `start.bat`
   - Linux / macOS: `./start.sh`
   - или `python sc_hub.py` (`python sc_hub.py --lang ru`, чтобы задать язык)
4. При первом запуске недостающие библиотеки (`pillow`, `flatbuffers`, `zstandard`, при возможности `numpy`) ставятся
   автоматически. Вручную: `pip install -r requirements.txt`.

Папки рядом со скриптом создаются сами:

| Папка | Назначение |
|---|---|
| `input/`  | сюда кладёшь исходники (`input.png`, `input.gif`, `input.sc`, …). Имя без пути ищется сначала здесь, потом в `output/`, потом рядом со скриптом. |
| `output/` | сюда сохраняется результат (`output.sc`, дампы, превью). Пункт 11 открывает папку. |

В любом вопросе про файл можно указать полный путь, а `?` откроет окно выбора файла.

## Подробное использование

### 1. PNG → SC
Превращает один PNG или все PNG папки в файл SC2.
- **ExportName** — имя, по которому файл подключается в игре/моде. Хаб печатает готовый блок `"FileName": "sc/…", "ExportName": "…"`.
- **Размер клипа** — коэффициент (`0.5` = вдвое меньше, `2` = вдвое больше) или итоговый размер `135x100`. Картинка создаётся в
  исходном качестве и масштабируется потом, поэтому большой пин можно уменьшить без потери чёткости.
- **Точка привязки** — от неё идёт масштабирование (центр, низ для объектов, стоящих на земле, углы…).
- **Режим масштаба** — масштабировать сам шейп (1) или матрицу клипа (2).
- **Расширенные настройки** — premultiplied alpha, свой размер шейпа до масштаба.

### 2. GIF → SC
Те же вопросы, что у PNG → SC, плюс: проигрывание туда-обратно, ширина кадра в файле (меньше — легче файл), превью первого кадра.
Размер гифки любой, прозрачность сохраняется.

### 3. Разобрать .sc
Печатает сводку (формат, блоки, экспорты, количества) и пишет подробный дамп `.txt` в `output/`. Работает для SC1 и SC2.

### 4. Переименовать экспорты
Переименовать один ExportName, заменить часть во многих именах или применить список из файла. Спрашивается имя результата.

### 5. Размер и положение
Масштаб (коэффициент) и сдвиг (px по X и Y) MovieClip'ов или Shape'ов. Выбор по ExportName, шаблону со `*`, id клипа или файлу-списку;
для шейпов — по id (`5, 7-9`) или по шейпам клипа. Показываются исходные fps и координаты.

### 6. FPS мувиклипов
Частота кадров (1–255) для одного клипа, всех экспортных или списка.

### 7. JSON/msgpack + PNG ⇄ .sc
Режим 1 разбирает любой `.sc` (SC1 или SC2) в `data.json` (или `data.msgpack`, если JSON больше 20 МБ) и PNG-атласы.
Режим 2 собирает `.sc` обратно из такой папки после правок. Результат проверяется повторным разбором.

### 8. Правка TextField'ов
Показывает, сколько текстов непустые, ищет по тексту (первые совпадения с id) или берёт id сразу; правка текста, размера шрифта и рамки.
Тексты, которые лежат в именах клипов / ключах локализации, тоже поддерживаются.

### 9. Перестроить атласы
Каждый фрагмент шейпа упаковывается заново в атласы до 4096 по стороне: максимальный размер, отступ, поворот на 90° ради плотности,
выброс пикселей вне контуров шейпов, выброс объектов, до которых не дойти ни от одного ExportName.

### 10. Удалить экспорты
Удаляет ExportName вместе с клипами и шейпами, нужными только им; можно сразу перестроить атласы, чтобы пиксели тоже исчезли.

### 12–13. Информация по ID, SC-пакет
Поиск объекта по id (родители, экспорты, текст). Поиск файлов разделённого пакета (`_tex.sc`, `.sctx`/`.zktx`).

### 14. Объединить
Склеивает папку `.sc` в один SC2 (пересечения id перенумеровываются, повторяющиеся имена экспортов переименовываются) или превращает
разделённый пакет в один файл. Можно включить ASTC.

### 15. Таблица текстов (CSV)
Выгрузка имён экспортов/текстов в CSV, правка в таблице, применение обратно.

### 16. Перенос экспортов
Перенос выбранных экспортов (со всем нужным) в новый `.sc` или добавление в другой файл.

### 17. Диагностика файла
Отчёт только из метаданных (без пикселей и текстов) — можно прикладывать к баг-репорту.

### 18. Очистить / оптимизировать
Убирает недостижимые объекты и сливает одинаковые; проверяет, что у каждого экспорта сохранился тот же отпечаток внешнего вида.

### 19. Создать фон меню
Собирает экспорт анимированного фона меню (имя по умолчанию `theme_bg`).

Положи в папку (пример — `examples/background/`):

| Файл | Значение |
|---|---|
| `gradient.png` | нижний слой (лучше 2048×1152; другие размеры, например 1848×1112, вписываются, пустые края заполняются размытием) |
| `symbol.png` | белый символ с альфой, множество копий плывёт по полю |
| `top.png` **или** `top.gif` | верхний слой (лучше 2048×1152, частично прозрачный; GIF — для анимации) |
| `flash.png` | необязательное свечение, пульсирующее за символами |

Вопросы: стадия (1 статика, 2 градиент + символы, 3 + верхний слой), единиц игры на пиксель (по умолчанию под 1383.12×778),
расстановка (шахматная / обычная / в разброс), плотность, ручная настройка символов (наклон, шаг, размер, скорость, прозрачность, поворот),
вспышка, сдвиг верхней части, экспортнейм, ASTC при желании.

### 20. Загрузочный экран
**Режим 1 — разобрать.** Укажи свой `loading.sc`. Хаб разрежет его в `output/loading_parts/`:
`background.png`, `logo_EN/KR/JP/CNT/CNS.png`, `supercell_logo.png` (лого SUP/ERC/ELL), `supercell_shine.png`, иконки и кнопки,
а также `template.sc`, `parts.json`, `README.txt` и `preview.png`. Части вырезаются строго по многоугольнику шейпа, поэтому соседние
объекты атласа в них не попадают.

**Режим 2 — собрать.** Правь PNG (любого размера) и/или отвечай на вопросы:
- свой фон (вписывание: закрыть с обрезкой / целиком / растянуть, дополнительный масштаб),
- одно лого игры для всех языков (+ масштаб),
- лого SUPERCELL в интро: оставить, заменить или **SUPERCELL → твоё лого** плавным диагональным переходом от левого нижнего угла к
  правому верхнему (длительность в секундах; интро становится длиннее на это время),
- ASTC при желании, имя результата.

Заменяются только те части, чей PNG изменился. Готовый файл разбирается заново, сохраняется `*_preview.png`.

### 21. Части .sc ⇄ .sc
Та же идея для **любого** `.sc`: режим 1 режет все одиночные прямоугольные шейпы (минимальный размер спрашивается, по умолчанию 12 единиц) в PNG
в `output/sc_parts/` вместе с `template.sc` и `parts.json`; режим 2 собирает обратно после правок PNG (спрашивается, как вписывать картинки
изменившегося размера). Шейпы из нескольких кусков и покадровые части остаются как в шаблоне. Результат всегда SC2.

## Советы и ограничения
- Храни оригиналы, правь копии.
- SC1 читаются и конвертируются; глубокие правки (пункты 20/21 и др.) пишут SC2.
- Файлы из нескольких частей (`_tex.sc`, `.sctx/.zktx`) — см. пункт 13; ASTC необязателен: он с потерями и медленный.
- Отчёты и дампы в файлы (`.txt`, `.csv`) всегда на русском; консоль следует выбранному языку.
- Английские тексты интерфейса переведены с помощью ИИ; поправки приветствуются.
